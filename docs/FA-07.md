# FA-07: Producer SDK and bounded local IPC handoff

**Candidate / source-side integration kit, not yet a running Vessie or PhiOS service.**

This rung implements the missing producer-to-receiver shape between FA-05/06 and the actual source formats. Production onboarding still requires wiring a native producer adapter into each upstream application and provisioning independent secrets under operator control.

## Why FA-07 uses metadata-first exports

Raw SuperPhiVessel DLAM context packets can contain task-specific prompts, restricted memories, model context and private source references. FA-06 could technically HMAC-seal a raw packet, but authenticating a secret does **not** make that content safe to copy into another agent or network. FA-07 therefore offers `vessie_metadata_export(original)` to validate the authentic shape and **derive a new, scrubbed packet** with:

- exact packet, task, namespace, agent and policy-epoch labels;
- SHA-256-derived model and ledger identity strings;
- `items=[]`, `memory_budget_tokens=0`, fixed observation-only purpose, target and authority reference;
- `action_authority=NONE` and no prompt contents, original purpose, original ledger pointer, profile or model ID.

This is a **derived export**, not byte-for-byte preservation or evidence of facts inside the source. A receiving WorkIntent must pin the **derived** packet digest. Original context items never enter the FA-07 envelope. The original Vessie schema version and FA-05 validation remain in place.

`phios_status_export(observation_dict)` accepts the *real contract shape* of PhiOS `PhiVesselBridgeObservation.to_dict()` for `BRIDGE_STATUS` only. It rejects lease status, proposal, actions, privilege flags and modified observation hashes. It does not invoke PhiOS.

## Producer-to-receiver flow

1. Source application obtains a Vessie DLAM context packet or PhiOS bridge-status observation using its **own governance** and passes a plain dictionary to the FA-07 producer function.
2. `issue_producer_envelope(...)` validates and redacts the source, seals the derived data with HMAC-SHA256, a fresh 128-bit nonce and a <=10-minute UTC window, and binds the work ID and locator. A shared secret is passed by the trusted integrating host, not loaded from the repository.
3. `frame_export` creates a 4-byte big-endian length prefix and <=75,000-byte canonical JSON payload. `decode_export_frame` refuses malformed/truncated/concatenated frames, duplicate JSON keys, nonfinite values and oversized declarations. **These functions never open a network socket.**
4. `admit_export_frame(journal, frame, ...)` delegates to FA-06's trusted-key lookup, matching FA-01 WorkIntent reference/digest, replayed FA-02 journal head, FA-05 export validator and atomic replay-nonce table.
5. The receiver emits a **read-only handoff receipt**. It never grants action authority, delivers model context, sends notifications, runs a command, or edits the work history.

A test uses a real `socket.socketpair()` to transport a framed payload inside one local process. This demonstrates byte framing and reassembly, **not** an independently authenticated cross-process, cross-host or persistent connection.

## Boundaries we did NOT cross

- This PR makes no changes inside SuperPhiVessel or PhiOS. An upstream runtime still has to call these functions.
- No network listener, open port, remote authentication, peer-to-peer transfer, or device coupling exists.
- No key exchange, secret vault, cryptographic hardware identity, human consent ceremony or remote revocation protocol is provided. HMAC verifies shared-key possession, not who a participant is.
- No model invocation, memory admission or prompt/context replay. The exported Vessie packet is metadata-only.
- SQLite nonce rejection applies only to the **same local DB and backups**. Rolling the database backward can reenable an old nonce.
- The receiving operator must pin the derived snapshot in WorkIntent *before* calling `begin_work`. Source-derived hashes and self-reported actor IDs are not independent evidence.
- PhiOS `execution_available=true` means reported capability only, not execution authority.
- There is no signed source provenance or complete freshness and consent chain. A local attacker with the secret can impersonate its configured issuer.

## Commands and tests

```bash
python -m unittest discover -s tests -v
python -m fieldaccord producer-demo
```

The demo uses a temporary SQLite DB, a synthetic producer object and a test-only key. No environment credentials, network endpoints or actions are used. The output redacts source content and key bytes.

## What to connect next

- **Upstream Vessie:** add an opt-in native hook at the qualified DLAM context-packet exporter that calls `vessie_metadata_export()` before any transport, without exporting raw memory items.
- **Upstream PhiOS:** add a read-only hook to `PhiVesselBridgeObservation.to_dict()` for `BRIDGE_STATUS` only; do not expose its `execute()` port or the ActionLease.
- **Local operator host:** securely enroll/rotate the producer HMAC keys, expose a narrowly scoped local authenticated IPC endpoint, anchor journal heads outside the SQLite DB, and supply revocation and replay recovery.
- **FieldAccord:** qualify the actual producer application against these contracts, including shutdowns, model swaps, clock skew, storage rollback and unauthorized cross-work forwarding.

**A bridge can carry a fact claim. It cannot carry authority.**

# FA-05: Vessie / PhiOS export review seam

**Candidate, offline, no live runtime wiring.**

Grounded in exactly two upstream source contracts, inspected at the following repository revisions:

- SuperPhiVessel `protocols/dlam-v0.1/schemas/context-packet.schema.json` on `06e5eaa0389c85a6d06fc06e1cc24a3c06caba95` (contract uses `schema_version="1"` and `action_authority="NONE"`).
- PhiOS `phios/phivessel_bridge.py` on `1ddc0ab0ad20f46254891bad3fd1424425cc90d8`, specifically `PhiVesselBridgeObservation.to_dict()` for `kind="BRIDGE_STATUS"`, `schema_version="phios.phivessel_observation.v0.1"` and SHA-256 over the observation body.

**This is NOT a general WorkObject adapter** or a direct PhiOS service integration. There is no stable WorkObject-to-FieldAccord API established here. This rung deliberately starts with narrow existing exports and exposes only metadata. A separate future adapter can be built once WorkObject's exact exporter, admission rules, and permission boundary are frozen.

## Contract

`inspect_interop(intent, events, export, *, source_kind, source_locator, expected_payload_sha256, expected_state_head, expected_task_id=None)`

Both the export digest and the FA-02 work-history head MUST be supplied independently from the export being evaluated. WorkIntent must request `discovery.read`, pin the exact source locator and digest in `context_refs`, and have an active, non-CLOSED replayed status.

### Vessie DLAM context packet (v1)

- Supported `source_kind="vessie.dlam_context_packet.v1"`.
- Explicit task binding is required: `expected_task_id` must equal the packet's `task_id`.
- Locator is `vessie:dlam:context:<packet_id>` and must already be pinned by WorkIntent.
- Validates required DLAM identity, epoch, budget, references, `action_authority="NONE"`, and bounded item structures.
- Output contains packet/task/agent/namespace identifiers, a **hash** of `model_ref`, claim-only policy epoch, hashed ledger frontier reference, and item count. It omits purpose text, content items, authority-decision reference, target surface, free-text instructions and memory data.
- `model_context_delivered=false`, `context_items_admitted=false`. An upstream context packet is **not** admitted to a model by this function.
- A model swap produces a new model hash; it cannot update grant state, promote evidence, or move context across boundaries.

### PhiOS PhiVessel bridge observation (v0.1)

- Supported `source_kind="phios.phivessel_observation.v0.1"`, `kind="BRIDGE_STATUS"` **only**. Does not accept LEASE_STATUS, GHOSTWALK_CONTROL, ActionLease, proposal or execution receipts.
- Locator `phios:phivessel:observation:<source_id>`, pinned in WorkIntent.
- Validates fields and the observation's canonical `observation_sha256` over its body, protocol version, schema, timestamp syntax, all five false authority/effect flags, and exact bridge-status payload.
- Exposes read-only *claims* that observe/propose/execute are available. Even `execute_available_claim=true` is **not** authorization, a verified connection, or proof of an executed action.
- No session token or lease digests are propagated.

## Cross-system refusals

- Missing/modified WorkIntent pin or FA-02 head.
- Unknown source type, unsupported version, wrong task ID, wrong locator, revoked/closed work.
- Extra Vessie authority fields, anything other than `NONE`, invalid budgets, non-object context items, oversized exports.
- Tampered PhiOS observation hash, time without timezone, unexpected embedded execution data or lease payload, asserted authority or effects, or altered bridge invariants.

Receipts always preserve `source_identity_authenticated=false`, `source_freshness_verified=false`, `authority_granted=false`, `action_executed=false`, `notification_dispatched=false`, `memory_admitted=false`, and `work_history_modified=false`.

## Why this is not yet production collaboration

The source objects, actor labels, and provided anchors can all be fabricated by an untrusted caller. Cross-project provenance requires independent authentication of identities and source export custody, revocation/freshness rules, and a durable work-history anchor under a separately trusted authority. Hash matching alone is not that trust boundary.

**Next milestone:** authenticated, permission-scoped source export with real integration tests against Vessie/PhiOS; do not import Vessie context into a model or initiate PhiOS actions until explicit native policy/consent checks are proven.

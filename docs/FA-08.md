# FA-08: native producer compatibility and opt-in hook boundary

**Candidate: real native object adapters, still no automatically running cross-repository connection.**

The FA-07 generic Vessie adapter was too narrow for actual P1-B `ContextComposer.compose()` output. The real producer additionally includes a domain-separated `packet_hash`, `packet_id=ctx_<prefix>`, `schema`, `authority_status`, `disposition`, tokenizer and admission metadata. Treating that full packet as a generic FA-07 context packet fails safely; silently allowing unknown fields would have been an unsafe fix.

## Exact source contracts reviewed

- SuperPhiVessel `packages/dlam-p1-v0.1/context_composer.py` and `dlam_store.py`, including `ContextComposer._seal()`; source main inspected at `c56dc658aaf3d6774b7f24dff94cd41e613683ce`.
- PhiOS `phios/phivessel_bridge.py`, including `PhiVesselBridgeObservation.to_dict()` and `observe(kind=BRIDGE_STATUS)`; source main inspected at `1ddc0ab0ad20f46254891bad3fd1424425cc90d8`.

## Native Vessie

`native_vessie_metadata_export(packet)` and `issue_native_vessie_envelope(packet, ...)` accept the **actual P1-B sealed packet dictionary** with an exact whitelist of known composer fields. The adapter recomputes the source's domain-separated SHA-256 (`PV-DLAM-CONTEXT|` + canonical JSON of the unsealed body), checks packet-ID derivation, enforces `schema_version=1`, `action_authority=NONE`, `authority_status=CURRENT`, and `disposition=READY`, and refuses unknown extensions or corrupted packets.

Only a narrow, explicitly selected field subset enters FA-07's existing metadata-only transform. Every prompt/memory item, query hash, excluded memory, tokenizer details, raw model identity, ledger frontier, original purpose and decision reference is dropped or replaced with a derived fingerprint. This is **not** preserving the original source hash in the export, nor a proof the source was produced by a trusted device. Source authorization is still an operator-owned question.

`issue_native_vessie_envelope` seals the DERIVED export, using the existing FA-07 bounded HMAC envelope. The receiver must pin the derived digest, not the original packet's digest.

Non-READY or stale/denied packets **cannot** even produce a metadata export in this rung. Source admission and permissioning remain inside Vessie's runtime.

## Native PhiOS

`native_phios_status_export(observation_object)` requires an object with `to_dict()`; it validates the exact PhiOS `BRIDGE_STATUS` format and its original `observation_sha256`, with all five authority/effect flags false. Dict input is disallowed at this native entry point to reduce accidental mixing of raw responses and native observations. This duck-typed method is **not** independent proof the object came from PhiOS.

`issue_native_phios_envelope(observation_object, ...)` seals a status-only observation for the existing FA-06 local journal. It never calls `PhiVesselBridgeService.execute`, `propose`, `LEASE_STATUS`, or any action adapter.

## Integration path after review

Vessie and PhiOS **still need their own explicit opt-in call sites** to hand native objects into this package. Neither application automatically loads this library, starts a listener, shares secrets, or dispatches from its production runtime in this PR. The library makes those native hook points concrete, so they can be tested by upstream projects without granting FieldAccord control over their governance.

A valid HMAC proves key possession, **not** a verified human, device or consent. SQLite nonce refusal is limited to the one DB, and local rollback can defeat it. Production needs independent enrollment, externally anchored journal heads, durable revocation/rollback recovery, and source-side approval policy.

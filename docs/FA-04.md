# FA-04: checked-in source pin and opt-in read-only public retrieval

**Status:** candidate / public-source experiment, not a distributed trust service.

## What is now real

The command `python -m fieldaccord fetch-fielddeck` may perform **one public HTTPS GET** for the exact GitHub Contents API endpoint

`https://api.github.com/repos/MichaelWave369/FieldDeck/contents/public/fielddeck.manifest.json?ref=b947a50aa552e47f05f88d4e0cfc5bdafc35d6b5`

with zero credentials, zero POST/write requests and zero execution routes.

The exact commit and expected Git blob SHA (`9116b57eed7a7ed62803459440ab2e0985222ac8`) are in `pins/fielddeck-v07.json`. The pin is intended to be held by the **human-reviewed FieldAccord source tree**, not read from the network response or an agent message. Updating to a newer FieldDeck manifest requires deliberately changing this reviewed file. This fixed source intentionally does **not** follow `main` updates.

The current deployed FieldDeck manifest version is 0.7.0 at the pinned commit. FA-04 extends FA-03 so it accepts explicit v0.6 and v0.7 source kinds without conflating their versions.

## Source verification chain

1. Build one URL from fixed repo/file constants and exactly 40 lowercase hexadecimal commit characters. No arbitrary URL, host, path or branch input.
2. Use Python stdlib HTTPS with system CA verification, default 8-second timeout, restricted JSON Content-Type and disabled HTTP redirect following.
3. Read at most 180,000 HTTP response bytes. Reject bad status, oversized headers/body and malformed responses.
4. Parse JSON with duplicate-key and nonfinite-value refusal.
5. Require a narrow GitHub Contents envelope: fixed file identity, `encoding=base64`, declared byte size, exact expected blob SHA.
6. Decode source, reject malformed Base64 and source exceeding 65,536 raw bytes. Recompute the Git SHA-1 blob identifier over exact bytes and compare it with the reviewed pin. Record the raw SHA-256 as an additional fingerprint. Git blob SHA-1 is not a signature.
7. Parse the source as strict JSON; validate the FieldDeck v0.7 policy: deny-by-default, authenticated runner required, free-form shell disabled.
8. Project **only** discovery action `id`, `kind`, `status`, `risk`. Strip task/payload/URL/IssueOps/agent text.
9. Optionally call `inspect_acquired_fielddeck` to bind the acquired snapshot to an FA-01 intent and replayed FA-02 work-history head using FA-03's existing review-only gate.

This protocol refuses mismatched pins, changed bytes, mismatched context digests and out-of-scope sources. Unit tests use an injected fake transport. The ordinary CI checks do **not** make network requests.

## What the evidence means

- A matching Git blob ID means the downloaded bytes have the expected Git object fingerprint, assuming the reviewed pin is trustworthy. The exact pinned commit in the GitHub API URL provides version targeting; remote host semantics still depend on GitHub and TLS.
- **Not authenticated:** who authored/approved that source, whether the data is current or correct, whether the human genuinely consented, or whether a security-sensitive event happened.
- FA-04 neither signs the result nor validates signed Git commits. It does not establish an authoritative timestamp, independent audit log or consensus.
- An application may deliberately keep consuming the same old pinned revision. **Freshness is not guaranteed**. Anti-drift is not equivalent to freshness or a generalized replay defense.
- The program returns `source_authorship_authenticated=false`, `authority_granted=false` and `action_executed=false`. All `ready` flags remain untrusted discovery metadata.
- The `inspect_acquired_fielddeck` function allows an injected pin only for tests/integrators. That can weaken the trust anchor if the caller treats an unreviewed pin as authoritative. The CLI offers no external pin override.
- API rate limits, TLS restrictions and unavailable GitHub can prevent optional fetching. The program fails visibly, without falling back to unpinned data.

## Tests

```sh
python -m unittest discover -s tests -v
python -m fieldaccord bridge-demo
# Explicit operator choice: makes a single public read-only HTTPS request
python -m fieldaccord fetch-fielddeck
```

On GitHub Actions, the default push/PR workflow is entirely offline. A **manual** `workflow_dispatch` run also enables the `manual-public-read` job that exercises actual public GitHub retrieval without tokens.

## What remains before calling this a trusted ecosystem service

External security review, full SHA-256 pinning, signed source/commit verification where relevant, authenticated operator/event provenance, authoritative append-only state store, source freshness policy, retries/backoff, modeled trust revocation, permission-scoped export of specific Vessie WorkObjects and PhiOS boundaries. A separate independently trusted grant must still be required for every external action.

**CAPABILITY ≠ AUTHORITY. DISCOVERY ≠ EXECUTION. PINNED ≠ TRUSTED.**

# FA-03: pinned, read-only source bridge

**Status:** initial candidate. The code is an offline snapshot processor, not a live connector or authority system.

## Why this rung exists

Field Accord needs to move useful *observations* between projects without turning discovery into command execution, memory into truth, or apparent operator identity into authorization.

This rung supports two **actually inspected** upstream formats:

1. **FieldDeck** public \`fielddeck.manifest.json\` v0.6.0, as discovery metadata only. The adapter reads only action ID, kind, status and risk, and it requires the source manifest's conservative policy defaults. "ready" means "listed as ready by FieldDeck", not permission to run it.
2. **NestedBubbleGear** \`NBG_EPISTEMIC_1\` memory records, preserving the claimed epistemic origin/confidence/evidence IDs while omitting free-form memory content and refusing to adopt \`actionAuthorized\`. A source claiming that authorization is quarantined.

There is **no speculative SuperPhiVessel/PhiOS wire adapter** in this rung. Their contracts can be incorporated once an exact stable read-only export is selected and tested.

## Contract

Function: \`inspect_snapshot(intent, events, snapshot, *, expected_state_head, expected_payload_sha256)\`

Inputs:

- A validated FA-01 WorkIntent, with \`discovery.read\` requested and a context reference containing the snapshot's exact locator + digest.
- An ordered FA-02 WorkEvent sequence; a caller-supplied expected head must match deterministic replay.
- A closed, versioned SourceSnapshot with same work ID, known source format/locator, actual payload and SHA-256 fingerprint.
- An independently held expected payload SHA-256.

The bridge does **not** obtain any of those anchors, download content, mint approval, persist an event, issue a notification, or make an API request. Callers are responsible for acquiring and protecting trusted anchors; passing the snapshot's own untrusted hash as an "expected" value is not provenance validation.

Every accepted candidate returns a BridgeReceipt containing a narrow redacted projection and:

\`provenance_authenticated=false\`  
\`authority_granted=false\`  
\`action_executed=false\`  
\`notification_dispatched=false\`  
\`history_modified=false\`

SHA-256 receipts permit reproducible fingerprint comparison but **not** cryptographic attestation of authorship or independent source authentication.

## Refusal and quarantine

- Reject unknown schema/extra envelope keys; wrong work ID or source kind; wrong source locator.
- Reject source digest drift relative to payload, WorkIntent context reference or caller-supplied digest.
- Reject stale/mismatched FA-02 expected state head, closed work, unsupported/unsafe FieldDeck policy, duplicate action/evidence IDs or invalid record types.
- Reject payloads larger than 65,536 bytes (canonical JSON).
- Quarantine, without granting authority, NBG records that **claim** \`epistemic.authority.actionAuthorized=true\`.
- Do not copy untrusted instructions, execution payloads, URLs, free-form text, or agent memory content into bridge projections.

# FA-06: local authenticated export admission and durable WorkEvent journal

**Candidate. Single-node local implementation. Not a live cross-device service or human authentication system.**

FA-06 adds a bounded shared-key authenticated export format and a local SQLite journal with conflict detection. Neither grants action permission nor runs an agent.

## Interfaces

- `sign_export_for_testing(...)` creates a versioned HMAC-SHA256 envelope over canonical JSON, including work ID, issuer/key ID, nonce, source kind/locator, payload digest and UTC validity. Never commit production secrets.
- `verify_export(..., keyring, now)` accepts only locally configured key + issuer + source-kind bindings, >=32-byte shared secrets, valid MAC, matching digest, canonical UTC timestamps and a <=10-minute window. This proves **shared-key possession only**.
- `WorkJournal(path)` stores frozen FA-01 intent and FA-02 WorkEvents in SQLite/WAL. Its `begin_work`, `state`, `append_event` and `admit_export` methods verify the full hash chain and expected head.
- `admit_export` checks HMAC, the separately supplied head, FA-05 `inspect_interop` policy, then reserves `(issuer_id, nonce)` in one `BEGIN IMMEDIATE` transaction. Duplicate nonces fail, including after reopening the same database. Failed admissions roll back.
- `append_event` implements compare-and-swap against the observed head, rejecting concurrent stale branches rather than last-writer-wins.

## Hard limitations

- Configured HMAC key possession is **not** proof of human/device identity, consent, or authority to perform any action.
- There is no trusted identity/consent ceremony, key provisioning or rotation API, hardware key store, global nonce ledger, signed certificate chain, or live connection to Vessie/PhiOS.
- SQLite's WAL and FULL sync improve local durability, but do not make the database immutable or externally anchored. Local administrators can rewrite it; rollbacks of old backups also roll back nonce guards. Keep an independently trusted head and secure/back up the DB.
- Payloads are inspected and redacted; no context is delivered into a model. No script, network request, notification, workflow, hardware instruction, lease issuance or external effects are performed.
- FA-05 still labels source provenance/freshness as unverified. A MAC cannot prove that semantic claims in the payload are true.

## Run

```sh
python -m unittest discover -s tests -v
python -m fieldaccord handoff-demo
```

The demonstration creates a temporary SQLite DB and an explicitly synthetic test key. It opens a WorkIntent, admits an HMAC-sealed Vessie-shaped context export, emits a redacted no-authority receipt and proves a replay is blocked. No network I/O.

## Negative controls

Bad key, wrong issuer/source role, payload tamper, expired window, extra grant field, oversize, wrong WorkIntent pin, mismatched task, stale event head, duplicate nonce, DB event corruption and conflicting writes must all refuse without running an action.

## Next boundary

Add explicit producer-side export functions in Vessie/PhiOS, out-of-band provisioning and revocation, independently anchored journal heads, cross-device replay controls, and authenticated operator consent before declaring the system trusted between hosts. PhiOS and FieldDeck keep exclusive authority over executing actions.
